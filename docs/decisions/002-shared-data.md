# 002: 공통 데이터 계층과 앱 어댑터

결정일: 2026-10-20 (한국 시간)

## 배경

웹 앱의 시설 조회·매핑은 웹 Supabase 인스턴스를 직접 참조했고 프로필 저장은 Capacitor Preferences에 연결돼 있었다. 모바일·토스에서 같은 조회 규칙과 저장 데이터 해석을 사용하기 위해 플랫폼 조립과 재사용 로직을 분리한다.

## 결정

- `packages/contracts`에 시설·설치 기구·기구 상세·프로필 DTO, `SiteRepository`, `ProfileStorage`, `Coordinates`, `LocationProvider`를 정의한다. 플랫폼 SDK·React·브라우저 전역을 참조하지 않는다.
- `packages/data`는 `createSiteRepository(client)`와 `createProfileRepository(storage)`를 public exports로 제공한다. SDK 버전은 기존 앱의 Supabase JS 2.117.2를 재사용하며 새 외부 라이브러리를 추가하지 않는다.
- Supabase 클라이언트 생성·인증·연결 설정 확인은 각 앱이 소유한다. 공통 조회는 공개 필터와 기존 테이블·사진 버킷을 유지하며 쓰기·스키마·정책 변경을 수행하지 않는다. 공개 필터는 RLS를 대신하지 않는다.
- 프로필 저장소는 문자열 읽기·쓰기 인터페이스를 주입한다. 웹은 Capacitor Preferences와 기존 `USER_PROFILE` 키를 연결한다. 손상된 저장 데이터·읽기 실패의 기본값 복원과 저장 실패 전달 동작을 유지한다.
- 브라우저 위치 조회는 웹의 `browserLocationProvider`가 공통 위치 인터페이스를 구현한다. 고정밀 요청·10초 제한을 유지한다. 모바일·토스는 자체 권한/위치 어댑터를 구현해야 한다.
- 웹 서비스는 기존 함수명과 타입 re-export를 유지해 화면을 연결한다. 공통 패키지는 앱을 import하지 않으며 `workspace:*`와 public exports로만 연결한다.
- 별도 `core`·`utils`·공유 UI·라우팅 패키지는 현재 필요하지 않아 만들지 않는다.

## 응답 검증과 오류

DB 응답은 객체·목록 구조를 확인한 뒤 매핑한다. 필수 식별자와 유한한 좌표 범위를 검증하며 숫자 문자열 좌표는 기존 호환성을 유지한다. 편의시설 상태·수량·선택 문자열은 안전한 기본값을 적용한다. 카탈로그 조인의 객체/배열 형태를 모두 지원한다.

상세 정보가 없으면 `null`을 반환하지만 조회 오류·잘못된 응답은 예외로 전달한다. 특히 설치 기구 조회 실패를 빈 목록으로 숨기지 않고 화면의 기존 오류 처리를 사용한다. 비공개 부모 시설의 기구는 반환하지 않는다. 개발 로그에 DB의 원본 오류·응답 데이터를 추가하지 않는다.

## 검증과 한계

후속 통계 준비로 `createEquipmentViewStatistics(client)`를 추가했다. 현재 토스 환경 플래그가 꺼져 있어 원격 쓰기는 실행하지 않는다. 선택 동의 검증·연령대/시도 최소 payload·DB 변경안의 적용 조건은 [통계 준비 문서](../view-statistics.md)에 기록한다. 웹 조회 서비스는 이 쓰기 기능을 호출하지 않는다.

루트 타입 검사·lint는 웹과 공통 패키지를 포함한다. 단위 검사는 웹 테스트 실행기에서 public exports를 통해 공통 저장소를 검증하고 Supabase의 fetch를 대체해 운영 DB에 접근하지 않는다. 기존 Chrome 흐름 검사는 fixture 기반이며 실제 서비스 권한·기기 검증을 대신하지 않는다.

실제 RLS·스토리지 정책, 배포 URL의 동작, PWA·모바일·토스 실기기 검증은 후속 항목이다. 기존 프로필 키와 선택 지점 키를 유지하지만 서로 다른 플랫폼/출처 간 저장 데이터를 자동 공유하지 않는다.
