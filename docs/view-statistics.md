# 기구 조회 통계 준비

토스에서 선택 동의한 사용자의 기구 선택 건수를 날짜·연령대·거주 시도·지점·설치 기구·동의 안내 버전별로 합산한다. 일별 집계 보관기간은 **90일**이다. 고유 사용자 수가 아니라 클릭 건수이며 재시도에 따른 정확히 한 번 집계를 보장하지 않는다. Web/PWA에는 전송을 연결하지 않는다.

## 월별 통계 별도 보관 기준

사용자 결정에 따라 개인을 식별할 수 없도록 처리한 월별 통계는 일별 집계와 분리해 장기 보관할 수 있다. 후보 항목은 월·거주 시도·연령대·기구 종류·조회 건수이며, 지점 ID·설치 기구 ID·일자는 장기 집계에 남기지 않는다. 기구 종류 분류와 실제 데이터 분포를 확인한 뒤 최종 집계 차원을 정한다.

월별 합산만으로 익명성이 보장되지는 않는다. 소수 조합은 지역·연령대·기구 종류를 더 넓혀 합산하거나 제외하며 다른 통계의 차이를 이용한 역추론도 검토한다. 조회 건수는 사람 수가 아니므로 특정 건수 이상이라는 조건만으로 익명성을 판정하지 않는다. 검토를 통과하지 못한 집계는 장기 저장하지 않고 90일 삭제 대상에 둔다.

현재 월별 자동 집계·장기 저장 테이블은 **미구현**이다. 기존 SQL은 일별 집계와 90일 삭제만 수행한다. 월 마감 후 원본 삭제 전에 집계하는 작업, 중복 실행 시 건수 중복 방지, 소수 조합 처리, 관리자 전용 권한을 구현·검증한 후 별도 마이그레이션으로 준비한다. 자동화 작업 실패를 이유로 일별 집계의 삭제를 늦추지 않는다. 월별 보관 안내를 반영해 동의 버전을 `2026-10-20-v2`로 변경했으며 이전 동의는 재사용하지 않는다.

출생 연도·성별·시군구·GPS·사용자 식별자는 통계 payload에 포함하지 않는다. 원본 프로필은 기기 저장소에 남는다. 출생 연도 또는 시도가 없거나, 동의하지 않았거나, 동의 버전이 바뀌면 보내지 않는다. 체크 해제 후 저장하면 이후 수집이 중단된다. 이미 합산한 건수는 개인별 분리가 불가능하다.

## 활성화 전 필수 확인

- [ ] 운영 DB 변경 승인 및 실제 `exercise_sites`, `site_equipment` 컬럼·공개 상태 확인
- [ ] 검증 환경에서 마이그레이션 실행, 기존 앱 조회 호환성 확인
- [ ] anon/authenticated의 통계 테이블 직접 조회·삽입·수정·삭제 거부 확인
- [ ] 공개 지점의 공개 설치 기구만 RPC 집계 가능하고 잘못된 시도·연령대·동의 버전은 거부되는지 확인
- [ ] 같은 날짜·차원 두 번 호출 시 한 행의 건수가 2 증가하는지 확인
- [ ] 한국 날짜 기준 89일 전 행 보존, 90일 전 행 삭제 및 cron 실제 실행·실패 알림 확인
- [ ] 개인정보처리방침, 처리 주체·문의처, Supabase 처리 지역·위탁/국외 이전 요건 및 서비스 로그·백업의 보관/삭제 정책 확인
- [ ] 공개 RPC의 위조·자동 반복 요청에 대한 호출 제한과 비용 보호 검토
- [ ] 실제 토스 기기에서 동의·미동의·철회·통신 실패 후 기구 화면 이동 검증

확인 전 `VITE_ENABLE_VIEW_STATISTICS=false`를 유지한다. 현재 운영 DB에는 적용하지 않았으며, SQL 실행·RLS·삭제 작업은 미검증이다. 최소 집계라도 법적 익명 정보라고 단정하지 않는다. SDK/서비스 인프라가 남기는 접속 로그는 payload와 별도로 검토한다. 집계 조회는 관리자만 허용하며 소수 집단 공개를 피한다.

## DB 적용 및 복구 검토

검토 대상은 `supabase/migrations/202610200001_equipment_view_statistics.sql`이다. 기존 테이블은 수정하지 않고 집계 테이블, 쓰기 RPC, 정리 함수, 일별 cron 작업을 추가한다. pg_cron이 없거나 UTC 시간대가 아니면 전체 트랜잭션을 중단한다. 한국 시간 자정에 90일 이상 지난 날짜를 삭제한다. 작업 지연 시 보관기간이 늘어나므로 모니터링이 필요하다.

적용 후 `cron.job`에서 작업명 `walk-fit-map-equipment-stats-retention`과 스케줄을, `cron.job_run_details`에서 실행 결과를 확인한다. 관리자 세션에서 정책·함수 권한을 확인하고 실제 anon/authenticated 연결로 접근 거부를 검증한다. 동의는 클라이언트의 선택이며 RPC만으로 진짜 사용자의 동의를 증명하지 못한다.

복구 시 먼저 환경 플래그를 끄고 다시 빌드·배포한다. 별도 운영 승인 후 해당 이름의 cron 작업을 `cron.unschedule(jobid)`로 중단하고 `record_equipment_view(text,text,text,text,text)`, `purge_equipment_view_statistics()` 함수를 제거한다. 집계 테이블 삭제는 데이터 삭제 승인을 별도로 받은 뒤 수행한다. 기존 시설 테이블과 정책은 건드리지 않는다.
